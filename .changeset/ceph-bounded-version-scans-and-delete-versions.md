Fixed "Delete Versions" (bucket header menu, versioned Ceph buckets) permanently deleting every object in the bucket instead of only its non-current versions and delete markers. It called the same full-wipe mutation as "Empty Bucket" with `includeVersionsAndDeleteMarkers: true`, which deletes every version and delete marker regardless of `IsLatest` and re-scans until the bucket is fully empty — so a bucket with one object holding old versions and another with only its current version ended up completely empty, the second object gone without ever having had a prior version.

A new `storage.ceph.objects.deleteNonCurrentVersions` procedure replaces that call for this action. It performs a single paginated scan of the bucket's version history and, per key, keeps the current version if it's a regular object, or removes the whole key (including the delete marker) if the current record is a delete marker — so live objects are left untouched while already-deleted objects are fully cleaned out of the "Deleted" tab with no way to restore them afterwards, which the confirmation copy now says explicitly. The scan defers deciding a page's last key-group until it has been fully read (S3 recomputes `IsLatest` at list time, so acting on a group split across two list pages before the second page arrives could otherwise "undelete" an object whose remaining version gets relabelled current). The modal now also distinguishes the three outcomes instead of reporting a silent success: a run that deleted nothing, hit S3-side failures and did finish scanning is an error, while anything that deleted some versions or stopped short of the end of the bucket is reported as a partial result in a warning notification that stays on screen until dismissed, since it asks the user to run the action again. Per-key failures and an unfinished scan are reported together rather than one instead of the other — the server records an error and sets `isPartial` for the same skipped key, so the two routinely occur on the same run.

Bound the S3 version scans behind folder and bucket state detection. `storage.ceph.versioning.checkDeletedContent` now performs a single paginated scan of the parent prefix (accepting a new optional `prefix` input) instead of one unbounded scan per folder, uses the standard 1000-key page size, honours the request abort signal, caps the scan at 20 pages, treats a truncated page that carries no continuation marker as a stop rather than a completed scan, and no longer swallows S3 errors. A new per-folder `isPartialScan` flag reports an incomplete scan (aborted, stopped at the page ceiling, or stopped on a truncated page with no continuation marker) instead of guessing, and the object browser shows such folders normally rather than hiding them. The flag is scoped to the folders the scan genuinely did not reach: a stop is reported against the last key actually read, so folders sorting entirely before it stay resolved. New `storage.ceph.containers.getState` procedure returns authoritative bucket emptiness/version flags in one request, replacing three truncation-prone client-side probes, which previously made "Empty Bucket" and "Delete Versions" disappear from the bucket menu on large buckets. It reports `isPartialScan` on the same three stop conditions, so `hasOnlyDeleteMarkers` is never asserted off a scan that never reached the end of the bucket.

Behaviour changes worth noting for consumers:

- `objects.deleteNonCurrentVersions` and `containers.getState` are both new procedures on the app router — the reason this is a minor rather than a patch. `deleteNonCurrentVersions` returns its own shape (`{deletedCount, errorCount, errors, isPartial}`) rather than the bulk-delete shape: no per-key `deleted` array, since this mutation scans a whole bucket and that list would grow with the bucket instead of with the caller's input.
- A key group `deleteNonCurrentVersions` cannot read — no record flagged `IsLatest`, or a record with no `VersionId` — is skipped and reported in `errors` rather than processed. Guessing in that state would have queued the group's live object for deletion by explicit version id, leaving no delete marker to restore from. A key with more versions than fit in the scan buffer is abandoned the same way instead of being accumulated in server memory. Each of those, an aborted run — including an abort that lands while the last page is being deleted — and a truncated page with no usable continuation marker sets `isPartial: true`, and the modal then warns that versions may remain instead of reporting a clean success.
- Callers that pass only `folders` to `checkDeletedContent` (the pre-existing input shape, still accepted) now get one scan of the folders' common parent prefix — falling back to the whole bucket when they share none — instead of N exhaustive per-folder scans. Such callers can therefore receive `isPartialScan: true` where they previously always got an exhaustive answer.
- `checkDeletedContent` now rejects two input shapes it used to accept: a request giving neither `prefix` nor `folders`, and a `folders` entry that doesn't live under `prefix`. Both used to return `isPartialScan: false` — the flag that means "this answer is reliable" — for folders the scan never visited.
- `checkDeletedContent` no longer swallows per-folder S3 errors and reports `hasDeletedContent: false`; a failure now surfaces as a tRPC error. Callers that relied on the silent degradation will start seeing errors they previously never saw.
- `containers.getState` establishes emptiness with its own single-key `ListObjectsV2` rather than from the bounded version scan, so `isEmpty` is exact on a bucket of any size and is never affected by `isPartialScan`. An unversioned bucket costs exactly two requests regardless of size, since it has no version history to scan.
- `containers.getState` takes `bucketName`, matching every other `containers.*` procedure, and returns the raw three-way `status` (`"Enabled" | "Suspended" | "Unversioned"`) alongside the collapsed `isVersioningEnabled` boolean. It has to issue `GetBucketVersioning` anyway, so a caller that needs to tell "Suspended" from "Unversioned" no longer pays a second round-trip to `versioning.getStatus` beside it.
- The shared Ceph S3 client now sets a 5s `connectionTimeout`, which applies to every Ceph request, so a Ceph endpoint that accepts no connection fails fast instead of hanging on the SDK's default (no timeout). `requestTimeout` and the retry count are deliberately left at their defaults.
