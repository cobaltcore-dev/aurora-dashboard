## What is already solid

- **Target surface** is settled: Aurora (`packages/aurora`), Juno UI components, the established tRPC/BFF + file-based TanStack Router patterns.
- **The reference implementation is complete and in production**, so the _behavioral_ contract (endpoints, cluster/worker/cloud-profile shapes, wizard steps, kubeconfig flows, permissions model, the oauth2-proxy error quirk) can be read directly from `plugins/kubernetes_ng` rather than invented. The enumerated reference endpoints are: cluster CRUD, `replace` (raw YAML PUT), two-step delete confirmation, `external-networks`, `cloud-profiles`, garden + admin `kubeconfig`, `gardener-api/info`, `scikube-getting-started`, and a capability `permissions` endpoint.
- **The feature list** (landscapes, kubeconfig download, instructions, add-cluster wizard, cluster list, cluster details, YAML editor) gives a clear starting inventory of stories.

The real gaps are **not** "what does the UI do" (the reference answers that) but the **Aurora-integration decisions**: how the BFF authenticates to Gardener (Q-C1), how landscapes map to Aurora's project/region model (Q-C2), how the non-catalog scope is gated (Q-C3), the MVP/parity boundary (Q-C4/C5), the YAML-editor/"just Juno" constraint (Q-C6), and the authorization contract (Q-C7).
